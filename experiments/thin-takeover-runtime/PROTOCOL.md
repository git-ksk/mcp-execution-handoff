# Thin Takeover Runtime wire contract v1

This document describes the experimental v1 data plane. It is intentionally narrower than a general remote-desktop protocol.

## Authority model

The data plane never grants authority. A control plane must first grant Human authority and provide a short-lived binding containing at least:

- principal;
- intervention identifier;
- epoch;
- client generation;
- absolute expiry;
- short-lived random 32-byte root transport key.

The runtime receives only the derived runtime binding. `Done`, `Cancel`, approval, and Agent resume remain authoritative control-plane operations and MUST NOT be inferred from a media/input packet. The runtime does expose one authenticated **local revoke signal** so the control plane can immediately tear down an already-granted Human transport without waiting for expiry.

Agent and Human input authority are mutually exclusive. Agent resume requires Human revoke, epoch advancement, fresh automation attach, and fresh semantic readiness verification.

The host converts the absolute control-plane expiry to a process-local monotonic deadline at startup. Media admission, media transmission and input injection must all fail closed after that deadline. Explicit Done/Cancel/revoke should send the authenticated revoke signal and terminate/revoke the runtime immediately instead of waiting for expiry.

A runtime restart or reconnect MUST use a fresh control-plane generation and fresh root transport key. Reusing a completed generation is a protocol violation even though the AEAD nonce itself is randomized.

## Cryptographic binding

`TransportCipher` uses ChaCha20-Poly1305. HKDF-SHA256 derives separate keys for each:

`sessionHash / epoch / generation / direction / channel`

Every sealed frame/event/control message carries a fresh random 96-bit ChaCha20-Poly1305 nonce generated by the crypto provider. The sequence number is authenticated replay/context metadata; it is deliberately **not** the AEAD nonce. This prevents nonce reuse if a process-local counter is reset.

Channels are:

1. video;
2. realtime input;
3. critical input;
4. revoke control.

Video is encrypted once per complete encoded frame or decoder-configuration blob, then the ciphertext is fragmented into MTU-bounded datagrams. This keeps AEAD work proportional to frames rather than packets.

## Video datagrams

`VideoPacketHeader` is a fixed 72-byte network-byte-order header containing:

- magic/version;
- flags;
- session hash;
- epoch;
- generation;
- frame ID;
- packet index/count;
- capture timestamp;
- encode-complete timestamp;
- 128-bit truncated HMAC-SHA256 routing-header authenticator.

The header authenticator uses a separately derived video-header key. Receivers MUST verify it **before** allocating or mutating frame reassembly state. Payload corruption/injection is still detected by complete-frame AEAD verification after reassembly.

Default datagram size is 1200 bytes to avoid common-path IP fragmentation.

Receiver policy is newest-frame-wins. Only bounded reassembly state is kept. A newer frame abandons an older incomplete frame. Completed frame IDs remain fenced for the lifetime of the generation so a previously accepted frame cannot be replayed after its assembly state has been released.

### Decoder-critical recovery

Ordinary delta-frame loss is not turned into an unbounded reliable queue. For an incomplete keyframe, a receiver may request a small number of missing packets only until a short frame deadline. After that deadline it requests a fresh IDR. IDR requests are rate-limited.

The first physical-network acceptance must measure loss at realistic encoded frame sizes. If bounded NACK/IDR is insufficient on the intended mobile path, FEC or codec/NAL-aware fragmentation is a transport evolution; it must not be hidden behind an unbounded retransmission queue.

## Input datagrams

Input uses two lanes:

- `realtime`: pointer movement and other replaceable state. Newest sequence wins; old/replayed events are dropped.
- `critical`: pointer buttons, keys, and text commits. A 64-sequence receiver replay window permits bounded retry while preventing double injection.

Each secure input datagram exposes only lane + sequence for routing/replay and encrypts the binary `InputEvent` with a lane-specific client-to-host AEAD key. The AEAD payload itself carries a fresh random nonce.

Suggested field semantics:

- pointer coordinates: normalized integer range `0...1_000_000` relative to the captured display;
- pointer button: `value=1` down, `value=0` up; payload may identify left/right/center;
- scroll: bounded signed x/y deltas;
- key: x carries platform key code, `value=1` down / `0` up;
- text commit: bounded UTF-8 payload.

Adapters MUST validate event kind/lane and bounds before OS injection. The host tracks pressed key/button state and releases all remaining pressed state when the lease is revoked, expires, or the input server exits.

## Immediate revoke control

`SecureControlCodec` uses the separately derived client-to-host control channel. The only v1 message is `revoke`.

- revoke packets are AEAD authenticated and sequence-fenced;
- receiving a valid revoke drops the shared process-local lease immediately;
- that same lease fences capture admission, media sends, and input injection;
- a revoke packet cannot grant Human authority, approve an action, or resume the Agent;
- malformed, replayed, wrong-generation, or unauthenticated control packets fail closed.

The standalone macOS host listens on a distinct control port (loopback by default). `takeover-control-send` exists as a minimal embedding/reference sender and reads key material from the environment rather than argv.

## Reconnect

Reconnect does not reuse stale authority. A reconnect must re-authenticate to the control plane and recover a **new** intervention generation/root key binding. Old generation keys and packets cannot reclaim a newer session. A reconnect after expiry requires a fresh control-plane grant rather than extending the old local lease.

## Credentials

Credential, OTP/MFA, passkey, cookie, token, framebuffer, and typed text material are ephemeral Human-plane data. They MUST NOT be returned to MCP/model context, argv, durable checkpoints, analytics, or ordinary logs.
